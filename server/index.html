Building a Simple HTTP Server in C

A practical introduction to the core concepts behind writing a minimal HTTP/1.1 server from scratch using plain C and sockets.

Written by Tristen Strydom · 11 September 2026

1. Overview

An HTTP server is a program that listens for incoming network connections, reads HTTP requests, and sends back HTTP responses. At its core it is just a TCP server that speaks the HTTP protocol.

Writing one in C forces you to understand the fundamentals: sockets, the request/response model, headers, status codes, and how browsers actually talk to servers.

A minimal C HTTP server typically does the following:

  • Create a TCP socket and bind it to a port (e.g. 8080)
  • Listen for incoming connections
  • Accept a client connection
  • Read the raw HTTP request from the socket
  • Parse the request line and headers
  • Generate and write an HTTP response
  • Close the connection (or keep it alive)

2. How a Request Arrives

When a browser visits http://localhost:8080/ it opens a TCP connection and sends something like this: 

GET / HTTP/1.1
Host: localhost:8080
Connection: keep-alive
User-Agent: Mozilla/5.0 ...
Accept: text/html,application/xhtml+xml,...
Accept-Language: en-US,en;q=0.9

The request ends with a blank line (\r\n\r\n). Everything before that blank line is headers; after it would be the body (rare for GET requests).

Key parts of the request line

  • Method – GET, POST, HEAD, etc.
  • Path – the resource being requested (/, /index.html, …)
  • Version – almost always HTTP/1.1

3. Parsing the Request in C

In a small server you usually read the entire request into a buffer (a few kilobytes is enough for most simple cases) and then parse it.

A common approach:

  1. Read bytes until you find the double CRLF that marks the end of the headers.
  2. Split the first line on spaces to extract method, path and version.
  3. Loop through the remaining lines and split each on the first colon to obtain header name and value.

Remember that header names are case-insensitive and that values may contain leading spaces after the colon. 

/* Simplified sketch */
char buffer[8192];
ssize_t n = read(client_fd, buffer, sizeof(buffer) - 1);
buffer[n] = '\0';

char *method = strtok(buffer, " ");
char *path   = strtok(NULL, " ");
char *version = strtok(NULL, "\r\n");

Real production servers use more robust parsers, but the idea above is enough to get a working educational server.

4. Sending a Response

An HTTP response has the same overall shape as a request: a status line, headers, a blank line, then the body. 

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 1234
Connection: close

<!DOCTYPE html>
<html>...</html>

Important headers for a basic server:

  • Content-Type – tells the browser what kind of data it is receiving
  • Content-Length – size of the body in bytes
  • Connection – close or keep-alive

After writing the response you can either close the socket or keep it open if you support persistent connections.

5. Next Steps

Once the basic request/response loop works you can start adding features:

  • Serve static files from a directory
  • Handle different routes / paths
  • Support POST requests and form data
  • Add simple logging
  • Implement basic keep-alive support
  • Handle more status codes (404, 405, 500, …)

Keep the code small and readable. Understanding every line is more valuable than having a feature-complete server at this stage.
